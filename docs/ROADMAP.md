## 再往后（M3）：免费服务器

这是项目名里的"免费资源"要兑现的地方。设计上已经留好了口子：

- `limits` 是通用额度模型（`requests_month` / `neurons_day` 之外加 `vcpu`、`ram_gb`、`egress_gb`）
- `category` 只是一个枚举，加 `compute` / `container` / `static-hosting` 不需要改主体结构
- 站点和 README 的渲染按 category 分栏

要注意，免费服务器比免费 API 乱得多：

- 免费 VPS 里混着大量挖矿陷阱和"免费"实则盗刷信用卡的骗局
- 免费 PaaS 的休眠策略、冷启动、额度重置规则普遍比 API 复杂
- 部分服务对同一用户的多个项目合并计算额度

所以这一阶段必须比现在更严：**每一条都要有人真的部署过东西**。

## 已决策的分歧：要不要开「需实名但长期免费」的二级表？

**结论（2026-11-17）：开。选方案 2。**

背景是当时最尖锐的矛盾：严格按零门槛筛，**「国内可直连」这一栏是空的**。

- 海外免费层（Cloudflare、OpenRouter、SambaNova、Groq…）多数要代理
- 国内免费层（智谱 GLM-Flash、硅基流动、魔搭、讯飞 Lite、混元 Lite…）几乎全部要实名或手机号

三个候选方案：

1. **保持现状**：只收零门槛，接受「国内直连」长期为空，靠英文清单的空白做差异化（但差异化的位置是空的）
2. **开二级表**：主表零门槛，副表"需实名/手机号但长期免费"，用一个 `tier` 字段区分，表头明确标注 ✅
3. **换个轴**：不再以"门槛"为主轴，改成以"国内可达性"为主轴，门槛作为标签

选 2 的理由：对中文用户来说国内免费层的实用性最高，"零门槛"的卖点靠**分开呈现 + 全程标注**来保住，而不是靠不收。实现上：

- `tier` 由 `requirements` 派生（`kyc`/`phone` 任一为 true 即 `kyc` 档），写不错、也绕不过
- 信用卡、邀请码仍然硬拒绝——二级表放宽的只是"注册时交身份信息"，不是"可能扣钱"
- README 二级表和网页卡片角标都会显示具体门槛（实名/手机）
