# 核验手册

这个项目的价值全在"有人说他真的看过"。所以核验不追求快，追求可追溯。

## 核验一条，只要五步

1. **打开证据链接**（`verification.evidence`），如果打不开，先找官方文档的新地址
2. **对着页面核这五项**：
   - 免费额度还在不在（数值有没有变）
   - 覆盖哪些模型（有没有缩水，比如把旗舰模型划到付费档）
   - 是否需要信用卡 / 实名 / 手机号（有任一项就应当归档）
   - 速率限制（RPM / RPD / TPM 的数值）
   - 额度重置周期（每天?每月?UTC 几点?）
3. **顺手实测可达性**：不用代理，直接访问它文档里给的 base_url
4. **改 YAML**：更新 `checked_at`、`evidence`，必要时改 `limits` / `models` / `cn_access`
5. **重建**：`python scripts/build.py`，确认没有报错

## 判据：什么情况该归档

| 情况 | 处理 |
| --- | --- |
| 服务下线 | `archived: true`，写明日期 |
| 取消免费层，改为付费 | `archived: true` |
| 免费层还在，但缩水了（少给模型/降额度） | 留在表里，改数字，在 `notes` 里说明"较 2026-xx 缩水" |
| 新增了信用卡/实名要求 | `archived: true`，并同步到 `docs/EXCLUDED.md` |
| 只是文档页改版 | 更新 `evidence` 链接即可 |

## 国内可达性怎么测

四条判据，从松到严：

- `direct`：不挂代理，`curl` 该地址能通，连续几次都稳定
- `partial`：能通，但明显慢、偶发超时，或需要特定 DNS
- `blocked`：完全不通（连接被重置 / 长时间超时）
- `unknown`：没测过，**不要猜**

顺手把测出来的现象写进 `notes`，比如"晚高峰超时率明显偏高"，比一个字母更有用。

## 常见坑

- **文档页 ≠ 实际额度**。控制台的实时 Limits 页往往比文档新，两者不一致时以控制台为准，并在 `notes` 里注明。
- **免费额度常常只覆盖部分模型**。别照着模型目录抄，抄进来的多半是付费的。
- **"免费"有时是"账户余额为正时免费"**，余额变负后免费模型也会 402。
- **别用官方给的示例代码当证据**。示例代码常年不更新，模型名早就下线了。

## 现在的待办

```bash
python scripts/build.py --stale
```

输出里分两类：

- **待首次核验**：从未有人验证过，优先级最高
- **超过 60 天**：曾经验证过，但可能已经变了

每周会由 CI 自动开一个 issue 汇总，直接认领其中一条即可。
